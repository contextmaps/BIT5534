Decision Trees
Duration: 75 minutes · Platform: Hokie AI · Submission: Thread exported as a .zip and uploaded to Canvas before leaving class · Lecture Mode: exploratory
Learning Objectives

By the end of this lecture, students will be able to:

  1. Count the cuts a decision tree tries on a numeric column and on a non-numeric column.
  2. Compute G squared for one cut and say why the tree keeps the cut with the largest.
  3. Follow a tree as it grows one split at a time and read the candidates table at any leaf.
  4. Build a decision tree tool from a specification whose three parts carry forward by different distances.
  5. Read a split history and defend a number of splits to stop at.
  6. Turn one leaf of a tree into a rule, and into an action for the people the rule describes.
Section 1 of 5
INTRODUCTION
📋 Note for Students

Last week's two methods found groups in a file that had no answer column, so nothing could say whether a grouping was right. Today's file has one. A hundred freshmen, seven things known about each of them, and whether each came back for a second year.

For the first fourteen minutes you watch. Four pictures and three formulas, and nothing to paste.

A hundred freshmen. Seventy seven came back for a second year and twenty three did not. The file knows seven things about each of them: GPA, miles from home, college, accommodations, part time work hours, how often they attend office hours, and high school GPA.

Which one question would sort the two groups best?

Count the cuts. GPA takes 99 distinct values among the hundred students, and a cut goes in the gap between two neighbors.

College has no order, so a cut there divides the five colleges into two groups. Count those too.

Every cut turns the column into a two by two table, below the cut against above it and left against returned. G squared compares the count in each cell, O, with the count E the cell would hold if the cut told you nothing.

The bottom half of the scan is that number computed for all 98 cuts. Now do the same for every column.

The split puts 11 students below 0.989, every one of whom left, and 89 above it.

The 89 are now a file of their own. The tree runs the same search on them, all seven columns and every cut, as if the other eleven had never been there. The whole algorithm is that one search, repeated.

💬 Discussion

Before the screen:

  • The eleven below the cut all left. Is there anything left to search for among them?
  • Among the 89, GPA has already been used. Can the tree use it again?

The specification below comes in three parts, sorted by how far forward they carry.

Part one is the same four lines as last week, and it holds for every tool you build in this course. Part two is six lines and it is new today. It holds for any model that predicts a category, so it comes back whenever the course reaches a classifier. Part three is six lines and it is the decision tree.

Class material
The specification you send
I want a Python script that shows everything in one window. Double clicking it opens it, and it also takes a file path as an argument.

- Read a .csv or .xlsx that I pick from a file dialog.
- Drop any row with a missing value in a column the analysis uses, and tell me how many rows you dropped.
- One window. A side panel holds the file, the column choices, the parameters and the save controls. The outputs go on tabs, one to a tab, each getting the full width. Open no second window.
- Never silently change a setting I have set.

- Let me choose one target column whose values are the classes to predict, and treat it as categories even when it is stored as numbers.
- Let me choose the input columns from all the other columns, numeric and non-numeric alike, and treat every non-numeric input as categories.
- Give each class one color and use that same color for it in every plot and in every table.
- Show a confusion table of actual class against predicted class, with the count and the row percentage in every cell, and the overall accuracy underneath.
- Save the predicted class and the predicted probability of every class for every row to a .csv when I ask.
- Use pandas, numpy, matplotlib, scipy and tkinter, and nothing else.

- Find each split by trying every input column and every cut. For a numeric column, try every point halfway between two neighboring distinct values. For a non-numeric column, try every way of dividing its levels into two groups. Score each cut by the likelihood ratio chi-square, G squared, of the table it makes against the target, and keep the cut with the largest G squared.
- Grow the tree one split at a time, always splitting the leaf whose best cut has the largest G squared, up to a number of splits I set with a control that steps up and down by one. Stepping down removes the most recent split.
- Draw the tree. Every node shows its count of each class and the rule that leads to it.
- Show a candidates table for a leaf I pick, with one row per input column giving its best cut, its G squared and its logworth, where logworth is minus log ten of the chi-square p-value.
- Plot the split history, entropy R squared against the number of splits, where entropy R squared is one minus the log likelihood of the tree over the log likelihood of the tree with no splits. Mark the current number of splits.
- Show a leaf report with one row per leaf giving its full rule from the root, its count of each class and its predicted class.

Ask me one question at a time about anything I have left unsettled, at most five questions, then write the finished prompt. Write no code until I send that finished prompt back to you.
