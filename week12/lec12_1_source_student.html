From a Desktop Tool to a Browser Page
Duration: 75 minutes · Platform: Hokie AI · Submission: Your reflection thread, exported as a .zip and uploaded to Canvas before leaving class · Lecture Mode: project_lab
Learning Objectives

By the end of this lecture, students will be able to:

  1. Separate a course tool's model functions from its window, and say what a server and a page each do in a browser version.
  2. Convert a course tool into a browser page with Hokie AI through a short series of modular prompts.
  3. Run the browser page on a laptop and check one of its numbers against the desktop tool on the same settings.
  4. Hold the team's agent beside the page in an iframe, as the first piece of the team's dashboard.

Class material
Prompt 2, plan the browser version
I want the same tool as a page in my web browser. Keep every function from your first list exactly as it is, and import them from reg_explorer.py rather than copying them. Plan two new files, reg_server.py and reg_page.html, with this design.
1. The server uses Python's built-in http.server module and no other web package. It handles three requests only. GET / sends the page. POST /open receives the data file and returns, for every column, its name, its kind as reg_explorer.py would guess it, its levels if it has ten or fewer, and whether it is a validation column. POST /fit receives every setting at once and returns the Fit tab as text and the two figures.
2. The page keeps every setting itself and sends nothing to the server when a setting changes.
3. Leave out Make the column and the Save buttons for now.
Give the exact field names of each request and each reply, as a short list. Do not write code yet.

To save a file from a reply, copy the code block with its copy icon and paste it into a plain text editor. On Windows, use Notepad, choose Save as type All files, and type the name exactly, such as reg_server.py. On a Mac, open TextEdit, choose Format, then Make Plain Text before you paste, and when you save, untick any option that adds .txt. Save into your folder for today.

Class material
Prompt 3, the server
Write reg_server.py from the plan. Follow these rules.
1. Use only modules that come with Python 3.13 or later, plus the packages reg_explorer.py already uses. Do not use the cgi module, which Python 3.13 and later no longer have. The page sends the data file as the plain body of the request, with the file name in a header.
2. Handle exactly the three requests in the plan, with exactly its field names.
3. Import reg_explorer without opening its window; reg_explorer.py opens no window when --selftest is in sys.argv at import time.
4. Refuse to fit when no validation column is chosen, and say so. Never make one on your own.
5. Draw the figures with matplotlib's Agg backend and send them to the page as PNG images.
6. Serve the page on port 8000. When it starts, print the address to open in the browser.
7. Put everything in the file, the imports included, inside one try block. If anything fails, print the error and wait for the user to press Enter, so the window stays open when someone double-clicks the file. Ctrl+C stops the server quietly, with no error text.
Give me the whole file.
Save the reply as reg_server.py in your folder.
