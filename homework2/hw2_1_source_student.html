Learning Objectives

By the end of this part, students will be able to:

  1. Run a single input logistic regression on a file the tool has not seen, and verify it against known values before reading any coefficient.
  2. Report an odds multiplier for a step size they choose, and say why one fitted coefficient returns a different multiplier for every step.
  3. Choose a step size for reporting an odds multiplier, and say what the choice of step size changes and what the choice of step size leaves unchanged.
  4. Separate the whole model test from the test on a single coefficient, and say what each one asks.
  5. Say what a contingency table holds, what the expected counts are, and what the chi-square statistic measures.
  6. Write a specification for an extension to an existing tool in their own words, and close its gaps through an interview they asked for.
  7. Obtain that extension, run it on three categorical inputs, and say what a significant test and a non-significant test each establish.

CASE TWO

Case two is worth 60 points, 15 for the first M block, 30 for the second M block and 15 for the reflection in the R block.

Case one fitted numeric inputs and left three columns untouched. Employment_Status, Housing_Status and Loan_Purpose hold categories and no number, so none of them can go into the tool you have. Contingency analysis is the method for a categorical input against a categorical response, and it is what case two is about. It lays the counts out in a table, works out what the counts would look like if the two columns had nothing to do with each other, and tests how far the real table sits from that.

You will learn it in the first M block and build it in the second. Work in the same thread.

Open the first M block and learn contingency analysis before you specify anything. No script comes out of this M block. Twelve turns is the ceiling.

By the end of the first M block you should be able to state the following four points in your own words.

First, what a contingency table holds, and how the expected count for one cell is computed from that cell's row total, that cell's column total and the number of rows in the file.

Second, what the chi-square statistic is built from, how the degrees of freedom follow from the number of rows and the number of columns in the table, and what a large value of the statistic indicates.

Third, the condition the test places on the expected counts before its p-value can be trusted, and what an analyst does when a cell falls below that condition.

Fourth, what the chi-square test reports about a categorical column that the logistic regression in case one could not report, and what the case one coefficient reports that the chi-square statistic cannot report.

Do not spend one turn on each of the four points. A single well-built opening question covers the first point and the second point together, which leaves you turns for the third point and the fourth point, and those are the two points that carry the case.

Two pieces of advice for the third point. The condition names a smallest expected count that the table has to reach, so ask Hokie AI what that number is and do not assume it. Then ask whether the condition applies to the observed counts or to the expected counts, because the observed counts and the expected counts are different quantities and the answer decides what your tool has to compute.

The fourth point is where case one and case two meet. Ask Hokie AI what a chi-square test reports, ask what it does not report, and press if the answer stays general.
