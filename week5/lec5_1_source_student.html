Learning Objectives

By the end of this lecture, students will be able to:

  1. Say what a cluster is in a data file, and say why looking at the data stops being a way of finding clusters once the file has more than three columns.
  2. State the merging loop that hierarchical clustering runs, including how many pairs of clusters are compared at a step where a stated number of clusters remain.
  3. Read a dendrogram as the recorded history of that merging loop, and set the number of clusters by choosing the height at which the dendrogram is cut.
  4. State what each of the five linkages takes as the distance between two clusters, and state what kind of cluster each linkage tends to produce.
  5. Specify and build a tool that clusters a data file, check the tool against merge heights and cluster sizes printed on this page, and profile the clusters the tool returns.

Section 2 of 5
DEMONSTRATION

Hierarchical clustering runs one loop. Every row starts as a cluster holding one point, so the seventy rows above start as seventy clusters. Find the two clusters closest to each other, merge those two clusters into one, and sixty nine clusters remain. Then do it again.

The loop stops when one cluster holds every point. What the method produces is not that final cluster. What it produces is the record of which clusters were merged, in what order, and how far apart they were each time.

The first two merges on the file above are worth following, because they show what the loop is actually doing before any tree is drawn.

Row 61 and row 62 are the closest two points in the file, so they merge first. Row 43 and row 51 are the next closest, so they merge second. Every other row is still a cluster holding one point at that moment.

Sixty nine merges later the loop has finished, and the whole history is drawn as one picture below. The bottom of the picture holds seventy clusters of one point each. The top holds one cluster with every point in it. The height at which two branches join is how far apart those two clusters were when they merged.

Reading the number of clusters off that picture takes one more step. Draw a horizontal line across it at some height, and count the branches the line crosses. Each branch the line crosses is one cluster. Lower the line and the count goes up, raise it and the count goes down.

The plot underneath the tree is the same information without the branches. It gives the height of every merge against the number of clusters that merge produced. Heights that rise slowly mean the loop is joining things that were close together anyway. A height that jumps means the loop has just joined two groups that were not close, which is the sign that it has run out of easy merges.

One thing in that loop has been left undefined, and it is the thing the whole method rests on. Finding the two clusters closest to each other requires a distance between two clusters. A distance between two points is settled. A distance between two groups of points is a choice.

Five choices are in common use and they are called linkages. Each of the five is a different answer to the same question.

The right hand panel of that card is the part to carry into your own run. Single linkage judges two clusters by their closest points, so a chain of points lying between two groups pulls them together and the clusters come out long and irregular. Complete linkage judges by the furthest points, which holds the diameter of a cluster down. Average linkage sits between single linkage and complete linkage. Centroid linkage throws away everything except the two means, which is why one far away point disturbs it less. Ward linkage asks what merging costs in squared error, and it tends to return clusters holding similar numbers of points.

Running Ward on the seventy points above, and cutting the tree at five, gives the groups below.
