Learning Objectives

By the end of this part, students will be able to:

  1. Read the number of clusters off a scree plot and name the two merge heights the reading rests on.
  2. Name the columns that make a cluster prominent in a parallel coordinates plot, and say what those columns being high or low would mean for the rows in that cluster.
  3. Describe a cluster whose profile has nothing prominent in it, and say what that flatness is evidence of.
  4. Say what changes in the cluster sizes when the linkage changes and the number of clusters is held fixed.
  5. Specify an extension to a tool they already have, obtain the build through an interview, and run it against a number printed on this page.
  6. Report the best number of clusters and its silhouette score for all five linkages, and say which linkages agree.
  7. Say whether a silhouette sweep and an elbow reading agree on the same file, and which of the two they would rely on.

CASE ONE

Case one is worth 50 points, 35 for the exchange in the M block and 15 for the reflection.

Open hier_explorer.py, load retail_stores.csv, take all six numeric columns, set store as the label column, leave standardize on, and leave the linkage on ward.

Check three numbers before you read anything else. The first merge is at height 0.1303. Cut at five clusters, the merge height is 5.0264 and the five clusters hold 40, 31, 28, 16 and 10 stores. If your screen agrees, the tool is computing what it claims to compute on the file this page is written about, and every number below is one you can compare against.

Four things are on screen and they answer different questions. The dendrogram shows which stores joined which, and in what order. The scree plot shows the height at which the tree drops to each number of clusters, and the place where that height stops falling steeply is the cut worth taking. The parallel coordinates plot draws one line per store across the six columns, coloured by cluster, and it is the only one of the four that tells you what a cluster is made of. The table underneath gives each cluster's mean on every column in standardized units, so a value near zero sits at the chain average, a value above one sits well above it, and a value below minus one sits well below.

Four moves, in order, and every move after the first uses what came back from the one before it. The card below carries them.

Move one claims the cut AND move two claims three profiles AND move three works through whatever the verdict disputes AND move four changes the linkage and reports what survived. All four.

Then in the same message, make your first claim. Say how many clusters you are cutting the tree into, and give the two merge heights that made you read it there, the one just above your cut and the one just below.

CASE TWO

Case two is worth 50 points, 35 for the exchange in the M block and 15 for the reflection.

In case one you cut the tree where the scree plot bent, and the reading was yours. and two people can read the same plot and bend it in different places. A silhouette score settles it with a number instead, because it asks of every store how close it sits to its own cluster against the nearest cluster it is not in, and averages the answer.

The tool you have does not compute it. Case two is where you add it, and the shape of the addition matters. Building a tree is the expensive part and cutting one you already have is nearly free, so a tool that builds the tree once and then cuts it at every number of clusters in turn can score twenty cuts for barely more than the cost of one. The pairwise distances behave the same way. Compute them once and every silhouette after that reads from the same table.

A scree plot you squint at becomes five rows you can compare.

Four moves, in order. The card below carries them.

Move one writes the specification AND move two closes the gaps it finds AND move three runs the build against a number on this page AND move four reads what the report says. All four.

Move one opens the block. Attach hier_explorer.py and write one paragraph specifying what you want added. Your paragraph has to carry four things. For each of the five linkages the tool already offers, build the tree once and cut it at every number of clusters from two to twenty. Score each cut with the average silhouette, computing the pairwise distances one time and reusing them. For each linkage report the number of clusters with the best score and what that score was. Print the five rows as a table and write the same table to a csv file in the folder the data came from. Say in the paragraph that you want at most five questions before the finished code, so the interview has an end.

Move two answers what it asks. It will have gaps to close, and the gaps are the point of asking for an interview at all. Answer plainly, say when you do not care about something and let it choose, and when it has what it needs ask for the finished file.

Move three runs it. Save the file it gives you as hier_explorer_silhouette.py in your hw4_1 folder, run it on retail_stores.csv with the same six columns and standardize on, and check one row before you trust the other four. Under ward the best cut is at five clusters with a silhouette of 0.5149. If your ward row agrees, run the rest and report all five rows in the thread.

Move four reads the table. Say which linkages landed on the same number of clusters and which did not, and say which linkage scored highest and which scored lowest.

One move is not one message. Twelve messages inside the block is the ceiling, and a ceiling is not a target. If the build does not run, the error and what you did about it belong in the thread. A thread showing a failure and a repair reads as more work than a thread showing neither.
