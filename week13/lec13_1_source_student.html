Live Data, a Sheet and a Site for an Agent
Duration: 75 minutes · Platform: Hokie AI, Google Sheets and Google Sites · Submission: Your reflection thread, exported as a .zip and uploaded to Canvas before leaving class · Lecture Mode: project_lab
Learning Objectives

By the end of this lecture, students will be able to:

  1. Give an agent an API Call to a public service for live data, and read the tool call and the values behind its answer.
  2. Publish a Google Sheet as a link and give an agent an API Call that reads it, so a change in the sheet changes the agent's answer.
  3. Embed an agent in a Google Site at an address anyone can open.
  4. Connect the team's own live source to the team's agent and use its value in a decision of the project.
Section 1 of 4
INTRODUCTION
📋 Note for Students

Today your agent reaches past its knowledge files. Every student builds a small Lumenvale release desk with two live sources and a Google Sheet, and puts it on a Google Site. Then your team connects its own live source, from the sheet below, to your project agent.

Your project agent knows what is in its knowledge files: the brief, your reports, your skill. A business decision often turns on something that changes every day, such as tomorrow's weather, today's exchange rate or the latest price index. Today your agent learns to fetch it.

An agent can reach outside its files in three ways. A live source is a public service the agent calls for today's data, such as holidays, a forecast or a rate AND a sheet is a Google Sheet the team keeps up to date, which the agent reads through its published link AND a site is a Google Site with the agent in a box, at an address anyone can open. Three connections.

Each one is an API Call or a link, set up in a few fields. You build all three on Lumenvale first, then connect your team's own live source.

The release desk takes three steps.

First, create the agent. In Hokie AI, create a new agent, and copy its Name and Description from the first box below. Paste the instructions into the Specific tab and the class Platform text into the Platform tab. Pick the model your instructor names, switch every capability off, delete the welcome message, and create the agent.

THEN add the two live sources. On the agent's edit page, click Add Knowledge Source and choose API Call. Copy the four fields of API Call 1 from the box below, one at a time, into the Name, Description, Parameter Schema and Endpoint fields, choose the Method GET, and click Add. Do the same for API Call 2. Both Parameter Schemas are empty, because each Endpoint already holds everything the call needs. Save the agent.

THEN ask. Start a thread with the release desk and ask the two questions below, one at a time. After each answer, open Execution Details and look at Tool Calls: the agent called the tool, and the values in its answer come from the response. Open each Endpoint in a browser tab to see the same response.

A sheet takes four steps.

THEN change a row. In the sheet, click the release date of LV-201, in cell D2, and replace it with the new date from the box below. Wait a minute, start a new thread and send the check question again. The desk reads the new date from the sheet.

A site takes three steps.

First, open sites.google.com/new and click Blank site. Click Untitled site at the top left and type Lumenvale release desk, then click the page title and type the same.

THEN embed the desk. In Hokie AI, open the release desk's Share and copy its link. In the site's Insert tab, click Embed, paste the link into the By URL box, and click Insert. Drag the corners of the box until it is wide and tall enough for a conversation.

THEN publish. Click Publish, type a web address that ends with your VT username, such as lumenvale-desk-jsmith, choose the public setting, and click Publish. Open the published site, sign in with your VT account inside the box, and ask the desk a question. Themes, colors, fonts and more pages are yours to explore later, on your own.

T Session Opener AI: acknowledge

Copy this block and paste it into Hokie AI to begin your session.

You are an analysis partner for BIT 5534 Applied Business Intelligence and Analytics, a graduate course in business intelligence and analytics at Virginia Tech. The student holds graduate standing, has some statistics background, and is working on a team analytics project. Speak to them as a capable adult. Be direct, say when something is uncertain or contested, and do not pad your answers. When a student pushes back on something you said, take the challenge seriously. Do not concede immediately to be agreeable. --- **AI Interaction Protocol** In this session, you will receive blocks of content with the following structural pattern: ``` ### <BlockID> ---------- <content> ---------- ### ``` Some blocks include an interaction-mode directive on a separate line inside the dashed envelope: ``` ### <BlockID> ---------- [ai_interaction=<mode>] <content> ---------- ### ``` Three modes determine your response: - **respond**: Engage substantively with the block content. Treat it as a prompt, question, or task that wants your analytical response. Default for S blocks (prompts) and X blocks (free exploration). - **acknowledge**: Confirm receipt with one brief sentence naming the block ID. Do not analyze, comment on, or expand on the content. The student is filing the block for the record, not asking for engagement. Default for T blocks (this opener), R blocks (reflections), M CLOSE blocks (closing markers), Q blocks (structured selections), and O blocks (ordering selections). - **archive**: Respond with only the block ID and nothing else. Used for batched archival pastes where even brief acknowledgment would clutter the thread. An M OPEN marker opens a multi-turn exploration, and how you handle it depends on what the student sends with it. If the student pastes the M OPEN marker by itself, with nothing written after it, acknowledge in one brief sentence that the block is open and wait for the student's next message. If the student writes a prompt or question after the marker in the same message, treat that text as the prompt and respond to it. Always acknowledge an M CLOSE marker. If a block has no explicit `[ai_interaction=...]` directive, apply the block-type default per the list above. This protocol applies for the remainder of this session. ---
