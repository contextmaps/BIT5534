Reading a Principal Component Analysis and Exporting Its Scores and Loadings
Platform: Hokie AI (build) + local Python (run) · Submission: Thread exported as a .txt and uploaded to Canvas
Learning Objectives

By the end of this part, students will be able to:

  1. Run a principal component analysis on a twelve column file and read the eigenvalue table the tool prints.
  2. State a reading of one component plane as a claim, have it checked against the data the reading came from, and say where the claim was overstated.
  3. Report how many components to retain under the eigenvalue rule, the cumulative percentage rule and the elbow, naming the threshold they applied.
  4. Say what changes in the retained count when the cumulative threshold moves from seventy percent to eighty.
  5. Decide whether a score plot holds outliers, and say what the decision rested on.
  6. Read a loadings plot for clusters, for the cluster that lines up with a named component, and for the variable the first two components represent least well.
  7. Write a specification for three exports an existing tool does not have, close its gaps through an interview they asked for, and check the exported numbers against the output they came from.

CASE ONE

Case one is worth 45 points, 30 for the exchange in the M block and 15 for the reflection.

Open pca_explorer.py, load Satellites.csv, take all twelve columns, and run the analysis. Leave the label column empty, because the file has no label column.

Check four numbers before you read anything else. The first eigenvalue is 3.4089 at 28.41 percent, the second is 3.2252 at 26.88, the third is 2.7616 at 23.01, and the fourth is 0.4592. If your table agrees, the tool computed what it claims to compute on the file this page is written about, and every number below is one you can compare against.

The eigenvalue table is on screen and you can read the three retention rules straight off it. The three you found for yourselves on Thursday are the eigenvalue rule at or near one, the cumulative percentage rule with a threshold you state, and the elbow in the scree plot. Read all three off the table before you open the block, and read the cumulative column at seventy percent and again at eighty. The two plots below it are a different matter. The score plot draws one point for each of the thousand passes. The loadings plot draws one arrow for each of the twelve satellite variables, S01 through S12, inside a circle of radius one. Both are drawn in one plane at a time, and the two boxes labelled across and up choose which components that plane uses. They move both plots together, so you can set PC1 across and PC2 up, and you can also set PC1 across and PC3 up, or PC2 across and PC3 up. What changes when you do is what case one is about.

One thing to know before you read the arrows. Where two or three arrows nearly coincide their labels are drawn on top of each other, so you will see something like S0107 where three labels overlap, which is information and not a defect in the tool.

Four moves, in order, and every move after the first uses what came back from the one before it. The first card below carries them and the second repeats the four numbers you are checking against.

Move one attaches the data, sets the terms, and makes your first four claims AND move two answers the verdict it gives you AND move three looks at the other two planes and puts that report through the same check AND move four says where you were overstating. All four.

Move one opens the block. Attach Satellites.csv and write a paragraph that says four things: that you have already run this analysis yourself in pca_explorer, that you are going to state what you observed and want it checked against the data, that it should tell you for each claim whether you are right, wrong, overstating or understating, and that it should not describe the analysis ahead of you or list results you have not asked about. Then ask for its own eigenvalue table, so its numbers sit beside the ones the tool printed.

Then make the four claims, all in that same message. Set the axis boxes to PC1 across and PC2 up first. From the loadings plot, which draws an arrow for each variable: how many clusters of arrows you count and which of the variables S01 through S12 are in each, which one of those clusters points along the PC2 axis, and which single variable has the shortest arrow. From the score plot, which draws a point for each pass: whether any point sits far enough from the rest to call an outlier.

Move two is where the exchange earns its place. Read the verdict claim by claim. Where it says you are overstating, ask what in the data makes it an overstatement and what a correctly stated version would be. Where you think it is wrong, say so and hold your ground until it gives you a number. You ran the analysis and it is reading the file, so a disagreement is worth settling and not worth conceding.

Move three is your own check, put through the same test. Set the boxes to PC1 across and PC3 up, look at both plots, then set them to PC2 across and PC3 up and look again. Write what you saw, naming variables, and ask it to check that report against the data the same way, right, wrong, overstating or understating.

Move four is the task. Say which of your claims were correctly stated, which you overstated and in what direction, and what you now say about the variable whose arrow was shortest at PC1 and PC2. Then compare its eigenvalue table against the one pca_explorer printed. If they differ, say by how much and whether any retained count you reported changes, and say which of the two you are treating as the authority for this homework.

One move is not one message. Ten messages inside the block is the ceiling, and a ceiling is not a target.
